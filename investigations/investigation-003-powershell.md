# Investigation 003 — PowerShell

## Alert Behavior

PowerShell execution matched the suspicious PowerShell detection.

## Investigation Flow

PowerShell process → Command-line analysis → Parent-process analysis → Sentinel detection → False-positive review → Analyst verdict

## Tested Behaviors

1. `Invoke-WebRequest` to `https://example.com`
2. `IEX()` with a harmless `Write-Output` command
3. A second controlled `IEX()` test

## Evidence Analysis

The investigation reviewed the PowerShell command line, account context, parent process, and surrounding activity.

Controlled PowerShell activity was successfully identified by the Sentinel detection.

The investigation also identified legitimate PowerShell activity generated by Azure Arc and Acer software. These events demonstrated why command-line context, account type, and parent process are important when investigating PowerShell alerts.

## Investigation Result

The controlled PowerShell events were intentionally generated to validate the detection. No malicious payload was used.

The `Invoke-WebRequest` and `IEX()` tests matched the expected detection behavior.

The legitimate Azure Arc and Acer PowerShell events were assessed as benign software or administrative activity rather than malicious execution.

## Analyst Lesson

PowerShell execution alone does not establish malicious activity.

A SOC analyst should review:

- Command line
- Account context
- Parent process
- Process chain
- Execution pattern
- Related events

A suspicious keyword appearing as plain text does not necessarily mean that the associated command was executed.

## Verdict

**Benign authorized lab activity. No malicious payload was used.**

## Response

No containment or remediation was required.
